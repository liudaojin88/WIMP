 i# 设计文档

## 1. 技术架构
### 1.1 技术选型
- 前端技术栈: 纯前端静态页，Bootstrap 5 + 原生 JS
- 后端技术栈: 无（前端模拟数据）
- 数据存储: 前端内存数组（模拟）
- 部署环境: 复用现有静态资源部署方式

### 1.2 系统架构
- 页面：独立时效设置页面（fulfillment-timeliness-setting.html）
- 依赖：复用 layout.html 的头部/侧栏/主题样式与公共脚本
- 核心模块：筛选区域、表格区域、分页组件、弹窗交互（新增/编辑/复制/查看/删除）

## 2. 详细设计
### 2.1 前端设计
- UI 设计：顶部筛选行（履约模式下拉、国家/地区下拉、开始/结束日期、重置、查询）；右上操作按钮“新增”；主表格；分页条；弹窗（表单/确认）。
- 组件/结构：
  - 筛选表单：select 履约模式、select 适用国家/地区、date 起止各一、重置按钮、查询按钮
  - 表格列：履约模式 | 适用国家/地区 | 对客时效(d) | 最后修改人 | 最后修改时间 | 操作（编辑/复制新增/删除/查看）
  - 分页：页码、上一页/下一页、每页条数下拉
  - 弹窗：
    - 表单弹窗：模式、国家/地区、时效最小/最大（天）、备注（可选），提交/取消；查看态只读；复制新增预填并作为新记录保存
    - 删除确认弹窗
- 状态管理（前端 JS 对象）：
  - dataSource: 原始数据数组
  - filtered: 筛选后数组
  - pagination: {pageSize, current}
  - currentRecord: 弹窗编辑/查看的对象
  - mode: "create" | "edit" | "copy" | "view"
  - filterState: {mode, country, startDate, endDate}
- 行为逻辑：
  - 查询：校验开始<=结束；过滤 dataSource；重置到第一页；刷新表格
  - 重置：清空筛选，恢复 dataSource 全量
  - 分页：切分 filtered 到当前页显示
  - 新增：清空表单，提交推入 dataSource，刷新
  - 编辑：填充表单，提交更新该项
  - 复制新增：预填表单，提交时作为新项（新id/时间）
  - 查看：只读展示，无提交按钮或禁用提交
  - 删除：确认后从 dataSource 移除，重算分页
- 校验规则：
  - 模式、国家/地区、时效最小、时效最大必填
  - 时效最小/最大为数字且 min<=max
  - 日期范围查询时 start<=end

### 2.2 后端设计
- 无后端；所有数据操作在前端内存完成。

### 2.3 目录结构设计
- fulfillment-timeliness-setting.html（新建）
- 复用 layout.html 的公共结构和样式
- 若需公共脚本，内联于页面底部

### 2.4 时效设置编辑页设计
- 页面：fulfillment-timeliness-edit.html（列表“编辑”跳转）
- 基础配置区：
  - 适用国家/地区：多选复选框（国家列表与截图一致，可前端数组驱动）
  - 履约模式：下拉单选（跨境直发/备货发货/本土直发）
- 时效设置表格：
  - 列：环节、描述、对客时效区间（最小/最大天数输入）、参与时效计算标识（下拉“是/否”）、超期判定规则（下拉 + 天数输入）、异常判定规则（下拉 + 天数输入）
  - 表单交互：区间校验 min<=max；选择超期/异常规则时需填写天数；输入限制为数字
- 数据与状态：
  - editState: { countries:[], mode:'', stages:[] }；stages 内含字段 {name, desc, min, max, participate, overdueRule, overdueDays, abnormalRule, abnormalDays}
  - 预填：从列表行模拟数据传递（前端对象），页面加载时写入表单
- 提交/校验：
  - 国家至少选一，履约模式必选；各行 min/max 必填数字且 min<=max；若选择规则需填天数
  - 提交仅前端校验与提示（无后端）；提供保存/取消按钮
- 导航与返回：可在页面提供“返回列表”按钮（或利用浏览器返回）

## 3. 质量保证
- 测试策略：前端手动验证（筛选、重置、分页、增删改查弹窗流程、编辑页表单校验与提示）
- 性能优化：表格分页前端切分，数据量中等即可满足；无需额外优化
- 安全：仅前端静态，无接口；文本渲染使用 textContent/innerText，避免 innerHTML 注入
- 监控与告警：不涉及
